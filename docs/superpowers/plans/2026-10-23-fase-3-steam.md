# Pulso · Fase 3 (Steam) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Un botón "Sincronizar con Steam" importa la biblioteca real (juegos, horas, última partida) y los logros, con historial de sincronizaciones y errores honestos.

**Architecture:** Edge Function `steam-sync` (POST, usuario comprobado en el código). Lógica pura en `_shared/steam.ts` con tests. El juego se deduplica por `game_external_ids (steam, appid)`; si no existe se crea con nombre y portada vertical de la CDN de Steam (`library_600x900.jpg`) y slug `steam-<appid>`. Logros por tandas: 25 juegos por sincronización (primero los jugados en las últimas 2 semanas, luego los nunca sincronizados, luego los de más horas), porque cada juego cuesta hasta 3 llamadas.

**Spec:** `docs/superpowers/specs/2026-10-22-pulso-design.md` §6

## Global Constraints

- Una sincronización cada 10 minutos por usuario (`sync_runs`); límite de la API de Steam: 100.000 llamadas/día.
- Perfil o detalles de juego privados → error `profile_private` / `games_private` con instrucciones, nunca una biblioteca vacía como si lo fuera.
- Lo importado lleva `source = 'steam'`; un juego que el usuario añadió a mano pasa a `steam` conservando estado, favorito y etiquetas.
- Juegos nuevos entran como *Jugando* si se han jugado en las últimas 2 semanas, si no como *Pendiente*; una resincronización nunca pisa el estado.
- Los porcentajes globales llegan como texto (`"80.9"`).

## Review Focus

1. Respuesta de `GetOwnedGames` vacía (`{}`) = detalles privados; `{ game_count: 0 }` = sin juegos.
2. `unlocktime = 0` en un logro conseguido → `unlocked_at` nulo, no 1970.
3. Juego sin logros (`has_community_visible_stats` falso o esquema vacío) → no se llama a la API de logros.
4. Dos sincronizaciones seguidas → la segunda recibe 429 con los segundos que faltan.
5. Progreso de logros visible solo según la privacidad de logros (vista `security_invoker`).
